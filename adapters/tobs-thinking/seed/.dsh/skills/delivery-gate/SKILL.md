# 交付闸

这是可执行记录，不是一段劝告。判定用本 Memory 里的 `node bin/adapt.mjs gate --record <文件>`。命令说不通过，就不能改口说通过。

## 什么才算交付

进度、开工事实、以及“还在做”换了个名字，都不是交付。审查消息本身不要再开一轮审查。

通过前要有两个不同的执行上下文。可以是同一个模型，但必须写明。没有第二个上下文，不能由一个人扮演两方。每轮双方都要互相问这句原话：你确定这是你能给出的最佳答案吗？每轮都要有各自的调用或运行编号、修订和复核。只是互相说同意，不算。

评分用固定版本 `2026-11-06.1`：正确 40、证据 25、安全 20、完整 15，满分 100。质量分和置信度分开写。置信度是根据证据做的估计，不是统计概率，必须高于 80，并且写明证据。硬性检查要全部通过。

每一轮相对上一版的质量分至少提高 5%，这一轮才算有效。上一版是 0 时不要硬套这个比例，标成无法衡量。不要为了凑 5% 去改基线或抬高满分。

满分附近升不满 5% 时，用证据判断是分数虚高、评分天花板不够，还是确实没有更好的做法。三种都要留下尝试对比和剩余边界。它们都不是通过，也不要为此发明豁免。最多 3 轮。缺证据就标未通过或待验证。

制作方不能在审查失败后自己签字通过。审批卡片不能跳过这个闸。对外发送、删除、付费和改安全规则仍走原来的确认。

没有真实的第二次运行记录时，闸的结果保持未通过。不要用文档把未测写成已测。
